# T22 前端子任务清单

T22 将 Figma 原型集成到 Flutter 客户端，按页面和交付物拆分为以下子任务。所有子任务初始状态均为 `TODO`；只有 Derek0120 明确验收后才能标记为 `DONE`。

## 通用实现与验收要求

- 先阅读相应的 `ui-design/<页面>/<页面>.dart`，将 Figma 转码稿作为视觉依据，补齐 imports、布局和业务逻辑，交付完整、可编译的 Flutter Widget；不能把转码稿原样作为最终页面。
- 使用项目 `DarkTokens` 和 `ui-design/asserts/` 中的资源；避免硬编码颜色、固定页面尺寸或自造图标路径。通过 `LayoutBuilder` / `MediaQuery` 适配不同窗口。
- 使用 Riverpod 管理页面状态。页面调用对应 Service 的 gRPC 接口；服务端是游戏状态和规则的权威来源，客户端不自行决定手牌、合法出牌、轮次或结算。
- 每个有副作用的请求使用 `request_id` 和适用的 `expected_version`；重试复用同一 `request_id`。涉及不可见手牌时仅展示服务端授权的数据。
- 发现现有 Service 接口无法满足页面需求时，先在 [`../docs/ServiceAIP-TODO.md`](../docs/ServiceAIP-TODO.md) 登记请求/响应及授权、幂等要求，再通过统一 Service 抽象调用；不要在页面中伪造接口或本地推算结果。
- 页面任务补充对应状态、错误和交互测试；最终通过 `flutter analyze`、`flutter test`，并验证 iOS、Windows、Web 的条件分支。

## 设计稿与需求差异清单

- 已提供 Login、Register、Lobby、GameTable、FriendList、FriendProfile、Chat、CreateRoomDialog 共 8 张页面 PNG；AppIcon 资源也已提供。当前未发现缺少这些页面的截图。
- 第 12 屏原型交互、第 13 屏动效、第 14 屏多平台适配在独立 TODO 中明确为连线/文字说明/布局调整，不要求新增 Frame 截图；这些文档目前仍是待设计说明，不是可直接对照的交互或动效稿。
- Lobby 原型的四个标签现按需求解释为普通、高手、至尊三个积分准入大厅，以及邀请制好友房；好友房只豁免积分准入，结算使用普通大厅系数，其他三类准入/系数保持不变。好友房只展示收到的邀请，不公开列出房间。
- Lobby 房卡原型还显示房主、观战/在线信息和牌局信息；`RoomSummary` 已有房主/观战/门槛字段，但 presence 和实际 Lobby 列表 gRPC handler 尚未实现，见 `docs/ServiceAIP-TODO.md`。
- 创建房间原型包含观战设置和积分门槛，`CreateRoomRequest` 已有对应字段，但服务端 Lobby 创建 API 尚未接线；GameTable 完整快照/事件字段和动效触发数据也有缺口，见 `docs/ServiceAIP-TODO.md`。这些字段不能由客户端伪造。
