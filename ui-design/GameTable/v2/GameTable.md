# GameTable 房间 / 牌桌需求

## 实现基线

- 基于 `master` 创建 `feat-GameTable-ui` 分支。
- 以同目录 `GameTable.dart`、`GameTable.png` 为视觉依据，以下行为要求优先于设计稿示例。
- 同时补齐 Protobuf、服务端房间 / 牌局接口和 Flutter 前端，完成端到端实现。
- 本次不实现房间聊天前端。

## 服务端权威

- 洗牌、手牌、底牌、合法操作、轮次、升级和积分由服务端决定，客户端不推算结果。
- 客户端使用生成的 Protobuf 消息；动作提交带 `request_id` 和 `expected_version`，相同请求重试复用编号。
- 实时状态和重连快照必须按身份过滤；禁止将未授权手牌或底牌发送到客户端后再仅靠 UI 隐藏。

## 界面与行为

### 1. Bottom cards panel · 底牌面板

- 游戏期间，仅最后定主或反主玩家的本人主视角显示底牌面板。
- 默认显示牌背；点击或鼠标悬停后展示底牌。
- 当前抄底环节结束后，所有玩家和旁观者均显示面板，并直接展示底牌。
- 底牌公开状态和查看权限由服务端确定。

### 2. Play Action · 玩家操作区域

- 只有玩家显示并可操作；旁观者不显示。

### 3. Spectator perspective · 旁观视角

- 只有旁观者显示主视角选择控件。
- 点击 1、2、3、4 切换到对应座位的主视角。
- 当前选中视角使用区别于其他选项的颜色。
- 视角切换由服务端确认；切换过程中不能残留上一视角的私密牌面。

### 4. Card visibility · 开牌 / 关牌

- 只有玩家显示开牌 / 关牌控件。
- 开牌：旁观该玩家主视角的旁观者可以观看其手牌。
- 关牌：旁观者不能看到该玩家手牌，只能看到公开出的牌。
- 旁观权限过滤由服务端执行。

### 5. levels-center · 双方级数

- 设计稿中的 A、8 仅为示例，实际级数随服务端牌局更新。
- “我方 / 对方”相对于当前主视角展示，不能写死队伍级数。

### 6. score-right · 得分

- 每局开局显示 0，随服务端得分更新。
- 得分小于 80 时使用常规颜色。
- 得分大于等于 80 时：守分方主视角显示红色，得分方主视角显示绿色。
- 旁观者按当前主视角所属队伍显示对应颜色。

### 7. Play buttons · 操作按钮

- 仅显示当前允许执行的操作，不能操作的按钮隐藏。
- 按钮种类以实际业务阶段和服务端允许操作为准，设计稿按钮仅为示例。
- 不在客户端自行实现出牌合法性或推算可用操作。

### 8. Room identity · 房间与局数

- 展示当前房间身份和当前局数。
- 局数从 1 开始，随服务端牌局更新。

### 9. 玩家座位顺序

- 修正设计图中反向的 1、2、3、4 座位顺序。
- 以 1 号位为主视角时：1 在下方、2 在右侧、3 在上方、4 在左侧。
- 切换主视角时整体旋转布局，当前主视角始终位于下方，物理座位编号不改变。

### 10. 庄家 lighter 贴图

- 使用 `../../asserts/ic_lighter/lighter.png` 标识本轮庄家。
- 标记跟随服务端本轮庄家更新，不以房主身份代替庄家身份。
- 非主视角庄家：贴图放在该玩家的段位旁边。
- 主视角玩家为庄家：贴图放在手牌最左侧，与底牌面板垂直对齐。
- 等待开局、尚未确定庄家时，不展示虚构的庄家标记。

## 适配与验收

- 客户端由用户在本地验证；服务端程序由 GitHub CI 验证。开发期间不主动运行本地 Go 或 Flutter 验证命令。
- 共享 iOS / Windows / Web，支持触控点击和桌面鼠标悬停。
- 使用项目设计 Token、自适应尺寸和既有卡牌组件。
- 验证玩家 / 旁观者权限、底牌显示阶段、开关牌、视角切换、级数 / 局数变化、79 / 80 分颜色边界、服务端动作约束和幂等 / 版本冲突。
- 对照同目录设计截图检查布局；设计图示例静态值不应覆盖真实服务端状态。
