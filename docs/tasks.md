## 状态规则

- 每项任务当前状态只能是 `TODO` 或 `DONE`；新任务一律从 `TODO` 开始。
- 只有 Derek0120 明确确认该项验收完成后，才能将状态改为 `DONE`。
- 代码提交、PR 合并或 CI 成功都不代表用户确认；不得自动将任务标为 `DONE`。
- 有待确认的产品/运维决策时，先记录选择并取得确认，再开始受其影响的任务。

## 已确认选择（T01）

以下选择会影响构建或发布，已按默认方案确定：

1. **iOS 打包**：暂不提供 iOS 打包 Action；如后续需要，须另行确认签名材料及分发方式。
2. **Windows MSIX 签名/分发**：使用 msix 工具默认的开发签名配置；正式分发前配置可信签名证书或 Microsoft Store 流程。自签名包的接收方需信任对应证书才能安装。
3. **服务端分发方式**：仅生成 Docker 镜像归档并上传至 GitHub Actions run，不自动推送到镜像仓库。
4. **架构文档第 13 节**：采用其中记录的默认决策；生产容量、备份及 RPO/RTO 数值在生产发布前明确，Web 插件与浏览器范围在技术验证中确定。

## 当前构建工作流约定

仓库目前尚无应用源码。工作流约定服务端位于 `server/`（含 `go.mod`、`cmd/server` 和 `Dockerfile`），Flutter 应用位于 `client/`（含 `pubspec.yaml`、Windows 工程及 `msix` 开发依赖/`msix_config`）。master 上的服务端代码变更构建 Linux/amd64 Docker 镜像归档；客户端代码变更构建 Windows MSIX。暂不提供 iOS 打包 Action。产物上传到对应 GitHub Actions run，不自动发布到商店或镜像仓库；MSIX 当前使用开发签名，正式分发前需配置经确认的签名证书或商店发布流程。
